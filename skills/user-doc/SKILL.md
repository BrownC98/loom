# 사람에게 보이는 문서

목업과 보고서는 같은 디자인 언어를 쓴다(2026-10-21 사용자 지시 "목업과 보고서는 동일 디자인 언어를 사용하도록 한다"). 만들기 → 점검 → 열기 → 확인을 한 번에 한다.

## 형식

- HTML 한 파일, 한국어. [style.html](style.html)을 복사해 시작한다. `<style>`의 토큰·글꼴·글자 크기·머리 줄·절 번호·표 모양을 바꾸지 않는다. 필요한 블록만 더한다.
- 기본은 라이트(`<html style="color-scheme: light">`)이고, 오른쪽 위에 [다크로 보기] 전환 버튼(`.theme-toggle`)을 둔다(2026-10-21 사용자 지시 "디폴트는 라이트").
- 맨 위 머리 줄: `응답할 곳: <역할> · <노드 이름>`(사람이 답을 보낼 노드), 목업은 `연 담당: <역할> · <노드 이름>`과 판 번호(`v2 · 날짜`)도 둔다. 노드 이름은 열기 직전에 `loom status`로 확인한다. 이름이 바뀌면 머리 줄도 바꾼다.
- 문서 ID: `show.sh`가 머리 줄 맨 앞(`문서 ID: M3`)과 `<title>` 앞에 붙인다. 목업은 M, 보고서는 R에 번호다. 같은 경로는 판이 바뀌어도 ID가 같다(표 `~/.cache/user-doc/ids.tsv`). 만든 사람은 ID를 쓰지 않는다. 채팅에서 문서를 말할 때 ID를 같이 적는다(2026-10-21 사용자 지시 "보고서, 목업 마다 id를 붙여서 상단에 표시해줘").
- `<title>`은 문서마다 다른 짧은 이름이다. 열린 창을 이 제목으로 찾는다.

| 종류 | 본문 |
|---|---|
| 목업 | 제목, 한 문단 배경(사람 지시 원문), 상태마다 ①②③ 번호 절과 실제 화면처럼 그린 바뀌는 구역만, 바뀌는 곳은 점선, 그림 아래 짧은 설명 목록, 끝에 「승인할 것」 표(권장안 표시). 데스크톱 폭 하나 |
| 보고서 | 제목, 첫 절에 결론, 본문은 표와 짧은 목록, 출처는 링크, 끝에 「정할 것」 표(권장안 표시). 조사·설계·점검 기록은 보고서에 쓰고 목업에는 쓰지 않는다 |

- 위치: 목업은 저장소 `docs/mockups/<이름>.html`, 보고서는 `~/.cache/loom-briefs/<작업>-<내용>.html`. 수정본은 같은 경로에 쓰고 판 번호를 올린다.

## 보이기

1. 만든 사람(코디·워커)은 파일을 쓰고 렌더를 점검한 뒤, 경로·판·한 줄 요약만 부모에게 보낸다. 사람의 브라우저는 열지 않는다.
2. 여는 사람(총괄, loom이 아니면 사람과 대화하는 에이전트)이 내용을 검수하고 [scripts/show.sh](scripts/show.sh)를 부른다: `bash <이 스킬 폴더>/scripts/show.sh <파일>`.
   - bash가 없는 기계(Windows 노드)에서는 `show.sh`를 부르지 않는다. 형식을 눈으로 점검하고 4번을 따른다. loom 터미널의 파일 링크는 누르면 데몬이 그 파일을 연다.
   - 형식을 점검한다(제목, 라이트 기본, 전환 버튼, 머리 줄). 실패하면 만든 사람에게 돌려보낸다.
   - 헤드리스 Chromium으로 그린 그림을 남긴다. 여는 사람은 이 그림을 본다.
   - Windows 기본 브라우저(WSL)나 `xdg-open`으로 연다.
   - 브라우저 창 제목에 문서 `<title>`이 보이는지 확인한다. 끝 코드 0만 「떴다」다.
3. 새 판도 매번 `show.sh`로 다시 연다. 「열린 탭을 새로고침하라」고만 하지 않는다(2026-10-21 「브라우저에 안뜨는데?」: 새로고침 안내만 하고 열지 않아 사람이 문서를 보지 못했다).
4. 끝 코드가 0이 아니면 「떴다」고 말하지 않는다. 사람에게 파일 링크를 주고 열렸는지 묻는다.
5. 채팅에는 한국어 요약, 파일 링크(markdown), 정할 것만 적는다. 표 전체를 채팅에 다시 쓰지 않는다.

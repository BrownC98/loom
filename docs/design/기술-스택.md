# 기술 스택

- `loom` Rust 실행 파일 하나가 데몬과 모든 명령을 맡는다. Windows, macOS, Linux에서 같은 코드가 돈다.
- 데몬: `tokio`, `axum`, `portable-pty`(Windows ConPTY 포함), `rusqlite`, `rust-embed`, `sysinfo`(중단할 셸의 프로세스 나무), `tokio-tungstenite`(Codex app-server 연결), `typify`(빌드 때 Codex 스키마에서 타입 생성), `ureq`(서버 HTTP), `base64`(OpenCode 계열 Basic 인증)
- 화면: React, React Flow, xterm.js. 빌드한 화면을 실행 파일에 넣는다. Linux·macOS에서는 사람이 브라우저로 연다. Windows·macOS에서는 앱 창도 연다(「데스크톱 앱」).
- API 타입은 Rust에서 한 번만 선언한다. TypeScript 타입은 `ts-rs`로 만든다.
- 워크트리와 커밋 그래프는 `git` CLI를 부른다.
- 개발 환경은 배포 환경과 같은 호스트다(「[배포](배포.md#배포)」). 실행 명령은 [AGENTS.md 「개발 환경」](../../AGENTS.md#개발-환경)에 있다.
- 노드를 띄울 때 `LOOM_URL`(노드 문 주소), `LOOM_SPAWN_URL`(데몬 주소), `LOOM_TOKEN`(노드마다 무작위 값) 환경 변수를 넣는다. SSH 노드는 앞의 두 주소를 받지 않고 노드 접속점(`LOOM_SOCKET`)만 쓴다. 사람이 띄운 셸·명령 노드를 뺀 모든 노드가 `LOOM_TASK_DIR`(「작업 폴더」)도 받는다. 에이전트용 명령은 이 값으로 데몬의 `/api/agent/*`에 HTTP로 요청한다. 데몬은 토큰으로 보낸 노드를 찾는다. 토큰은 노드와 함께 DB에 둔다. 노드 프로세스는 데몬이 다시 시작해도 살아 옛 토큰을 계속 낸다.
- 노드의 `PATH` 앞에 `loom` 실행 파일의 폴더를 넣는다. 노드는 설치 없이 `loom`을 부른다.

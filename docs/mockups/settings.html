loom 설정: 에이전트 등록, 계정, 사용량

Orca의 「Agents」「Accounts」 설정과 상태 표시줄 사용량을 loom에 옮긴 목업이다. 바뀌는 구역만 그렸다. 폭은 1440 데스크톱 하나다. 승인할 것은 셋이다: ① 맨 아래 「결정표」의 넣기·빼기, ② 각 구역의 화면, ③ 「구조 제안」의 모듈 배치.

1. 화면 맨 아래: 사용량 상태 줄과 [설정]

문제점지금 쓰는 Claude·Codex 계정과 남은 사용량을 볼 곳이 없다. 설정으로 가는 진입점도 없다. 개선 사항Orca처럼 화면 맨 아래에 늘 보이는 상태 줄을 둔다. 공급자마다 한 칸에 계정과 5시간·주간 남은 비율을 보인다. 칸을 누르면 2번 팝오버가 열린다. 줄 오른쪽 끝에 [설정]을 둔다.

2. 사용량 팝오버: 계정 바꾸기

문제점새 화면이다. 비교할 「전」이 없다. 개선 사항Orca 상태 표시줄 팝오버와 같은 일을 한다. 쓰는 계정의 두 창 비율과 초기화 시각을 보인다. 계정을 눌러 다음 새 노드가 쓸 계정을 바꾼다. 이미 도는 노드는 그대로다.

3. 설정 창 「에이전트」 탭

문제점에이전트가 Claude Code·Codex 둘로 고정돼 있다. 설치한 다른 CLI(Gemini, Cursor, OpenCode 등)를 노드로 띄우려면 「직접 입력」에 명령을 매번 적어야 한다. 개선 사항Orca 카탈로그 45개를 데이터로 옮긴다. 데몬이 PATH에서 설치된 것을 찾는다. 사용자는 쓸 것만 켜고 기본 에이전트를 고른다. 설치하지 않은 것은 접어 두고 문서 링크만 보인다.

4. 설정 창 「계정」 탭과 로그인 창

문제점노드는 늘 사용자의 기본 로그인(~/.claude, ~/.codex)으로 뜬다. 계정 하나가 한도에 닿으면 다른 계정으로 바꿀 방법이 없다. 개선 사항Orca처럼 공급자마다 계정을 여럿 둔다. 계정마다 loom이 만든 로그인 폴더(~/.loom/accounts/<공급자>/<id>)를 쓴다. [계정 추가]는 아래 로그인 창에서 CLI 로그인을 띄운다. 사용자의 기본 로그인 폴더는 고치지 않는다.

5. 새 노드 창: 프로필 → 에이전트

문제점「프로필」 칸이 Claude Code·Codex·직접 입력 셋으로 고정돼 있다. 설정에서 켠 에이전트를 고를 수 없다. 개선 사항「에이전트」 선택 칸으로 바꾼다. 켠 에이전트와 「직접 입력」만 보인다. 기본 에이전트를 처음에 고른다. Claude·Codex를 고르면 쓸 계정을 한 줄로 보인다.

노드 카드 머리의 「Claude Code」 글자는 에이전트 이름(카탈로그의 label)으로 바뀐다. 카드 모양은 그대로다.

사용량 갱신 주기데몬이 5분마다, 팝오버를 열 때, [새로 고침]묻는다Orca의 주기는 확인하지 못했다. 5분이면 공급자 API의 429(요청 제한)를 피한다. 다른 값이 필요하면 말한다.
계정 고르는 단위공급자마다 「쓰는 중」 계정 하나. 새 노드가 그 계정으로 뜬다묻는다Orca와 같다. 다른 안: 새 노드 창에서 노드마다 계정을 고른다. 칸이 하나 늘어난다.

구조 제안: 모듈, 파일, 인터페이스

AGENTS.md 10절에 따라 구현 전에 확인받는다. 레이어 규칙(docs/design.md 「레이어」)을 따른다: 기능 모듈끼리 부르지 않고, 데몬 라우트가 엮는다.

레이어·파일바뀌는 이유맡는 일과 인터페이스
기능 · src/profile.rs + src/agents.jsonCLI 버전, Orca 카탈로그카탈로그를 데이터로 둔다(id, label, 실행 명령, 별칭, 문서 링크, 첫 지시문 방식, 메시지 연동). catalog(), detect(&Agent) -> Option<PathBuf>, command(&Agent, brief, env, cwd). Start는 Agent { agent, brief }·Command { line } 둘이 된다. 첫 지시문 방식은 enum Prompt { Argv { separator }, Flag(&str), None }이다.
기능 · src/accounts.rs공급자 로그인 폴더 형식Provider { Claude, Codex }, AccountId. 계정 목록의 원천은 ~/.loom/accounts/<공급자>/ 폴더다. list(Provider)(이메일은 각 폴더 파일에서 읽는다), create(Provider) -> (AccountId, 로그인 명령), remove, launch_env(Provider, AccountId) -> Vec<(키, 값)>(CLAUDE_CONFIG_DIR, CODEX_HOME).
기능 · src/usage.rs공급자 사용량 APIfetch(Provider, 로그인 폴더) -> Usage { session: Window, weekly: Window }, Window { used_percent, resets_at }. 결과는 데몬이 계정마다 5분 캐시한다.
저장 · 2단위 저장 모듈저장 형식설정 세 값: 끈 에이전트 목록, 기본 에이전트, 공급자마다 쓰는 계정. 「큐」 브랜치가 main에 병합된 뒤 그 모듈의 표에 더한다.
조합 · src/daemon.rs화면 요구GET /api/agents, POST /api/agents/refresh, PUT /api/settings, GET /api/accounts(사용량 포함), POST /api/accounts/{공급자}(로그인 PTY id를 돌려준다), PUT /api/accounts/{공급자}/active, DELETE /api/accounts/{공급자}/{id}, POST /api/usage/refresh. 로그인 PTY는 기존 NodeHost로 띄우고 노드 목록에 넣지 않는다.
상호작용 · web/src/화면새 파일 Settings.tsx(창과 두 탭), StatusBar.tsx(하단 상태 줄과 사용량 팝오버). 고칠 파일 NewNodePopover.tsx, NodeCard.tsx(label), App.tsx(화면 맨 아래 줄), api.ts. 로그인 창은 기존 Terminal.tsx를 쓴다.

조각 순서

  1. 로직 A: 카탈로그·탐지·Start 변경과 /api/agents. 저장과 무관하다. 지금 시작한다.
  2. 로직 B: 계정 폴더·로그인·사용량 조회와 계정 API. 쓰는 계정 선택만 저장이 필요하다. 그 전에는 「시스템 기본」을 쓴다.
  3. 로직 C: 설정 세 값의 저장. 「큐」 브랜치 병합 뒤 시작한다.
  4. 화면: 1~5번 구역. 로직 A·B를 합친 뒤 시작한다.

확인하지 않은 것

  • macOS에서 Claude 토큰은 키체인에 있다. 첫 구현은 .credentials.json(Linux·Windows)만 읽고, macOS에서는 「사용량을 볼 수 없다」를 보인다.
  • Codex 로그인은 브라우저 콜백(localhost 1455 포트)을 쓴다. 도커 개발 컨테이너 안에서는 끝까지 확인할 수 없다. 호스트에서 확인한다.

점검 기록

  • impeccable detect(2026-10-19, 1회): 3건. 「얇은 테두리와 넓은 그림자」 2건은 설정 창 테두리를 지워 고쳤다. 「제목 크기 단계가 평평함」 1건은 문서 제목을 26px·20px로 키워 고쳤다. 제품 화면 글자 크기는 main.html 승인본을 그대로 쓴다.
  • WIG(1회): 아이콘만 있는 버튼에 aria-label을 달았고 장식 아이콘에 aria-hidden을 달았다. 네이티브 select에 배경색과 글자색을 정했다. 숫자는 tabular-nums다. 구현 때 지킬 것: 계정 지우기는 확인 창을 띄운다. 초기화 시각은 Intl.DateTimeFormat으로 쓴다. 긴 이메일은 말줄임한다. 설정 창은 overscroll-behavior: contain을 쓰고 열린 탭을 URL hash(#settings/agents)에 둔다. 경로와 명령은 translate="no"를 단다.
  • 오탐으로 둔 것: WIG의 「placeholder는 …로 끝낸다」는 승인본 main.html의 문장형 한국어 안내와 맞지 않아 그대로 둔다.

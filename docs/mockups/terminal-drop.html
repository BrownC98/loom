노드 터미널: 파일을 끌어다 놓아 경로 입력

사람 지시: 「loom 터미널 파일입력 방식에 드래그앤드랍 구현」. 탐색기·바탕 화면에서 파일을 노드 터미널(카드, 펼친 터미널, 오른쪽 칸)에 끌어다 놓으면 loom이 파일 경로를 그 터미널에 붙여넣는다. 에이전트 CLI는 그 경로로 파일을 읽거나 첨부한다. 바뀌는 구역은 터미널 위뿐이다. 점선이 바뀌는 곳이다.

① 끌고 있음 터미널 위에 파일 2개

파일드롭runningclaude-opus-5-5 · medium
✻ Welcome to Claude Code · ~/loom/workspaces/loom/파일드롭 >
놓으면 파일 경로를 입력합니다 파일 2개 · 파일마다 32MB까지
2보고서 초안.pdf
  • 포인터가 있는 터미널 하나에만 층을 덮는다. 터미널 밖으로 나가면 층이 사라진다.
  • 글이나 링크를 끌면 층을 보이지 않고 아무것도 넣지 않는다. 파일만 받는다.
  • 카드 터미널, 펼친 터미널, 오른쪽 칸 터미널 모두 같다. 머리만 보기 카드에는 터미널이 없으므로 받지 않는다.

② 놓은 뒤 경로를 붙여넣음, 엔터는 누르지 않음

파일드롭runningclaude-opus-5-5 · medium
✻ Welcome to Claude Code · ~/loom/workspaces/loom/파일드롭 > '/tmp/loom-paste/1761030512/보고서 초안.pdf' '/tmp/loom-paste/1761030513/로그.txt'
  • 파일마다 데몬에 올린다. 데몬은 원래 파일 이름 그대로 임시 폴더(<임시>/loom-paste/<번호>/)에 쓰고, 그 경로를 돌려준다. 그림 붙여넣기와 같은 폴더·같은 경로 방식이다.
  • 경로는 작은따옴표로 묶고 빈칸으로 나눈다. 끝에 빈칸 하나를 둔다. 빈칸·한글 이름도 그대로 읽힌다.
  • 붙여넣기만 한다. 엔터는 사람이 누른다. 놓은 터미널에 포커스가 간다.
  • 강조(파란 바탕)는 목업에서 붙여넣은 글을 보이려는 표시다. 실제 화면에는 없다.

③ 너무 큰 파일 · 폴더 오류 줄, 다른 파일은 그대로 입력

  • 오류는 지금 그림 붙여넣기 오류와 같이 터미널 화면에만 쓴다. 에이전트 입력에는 들어가지 않는다.
  • 큰 파일은 올리기 전에 화면이 거른다. 오래 걸리는 업로드가 생기지 않는다.
  • 받을 수 있는 파일만 ②처럼 붙여넣는다.

승인할 것

결정권장안다른 안
①~③ 화면과 문구그대로—
경로 얻는 방식권장: 브라우저·Windows 앱 모두 파일을 데몬에 올리고 그 임시 경로를 붙여넣는다. 데몬이 WSL에 있어도 노드가 읽는 경로가 된다.Windows 앱만 원래 경로(C:\Users\…)를 붙여넣는다. WSL 노드는 그 경로를 읽지 못해 /mnt/c/…로 바꾸는 부품이 더 든다. 원본을 고치면 에이전트가 원본을 고치는 차이도 생긴다.
받는 파일 종류권장: 모든 파일. 에이전트가 글·PDF·코드·그림을 모두 읽는다.글·그림만 받는다.
크기 상한권장: 파일마다 32MB(그림 붙여넣기와 같다).더 크게(예: 200MB). 업로드 동안 기다림이 생긴다.
폴더권장: 받지 않고 ③ 오류를 보인다.폴더 안 파일을 모두 올린다.

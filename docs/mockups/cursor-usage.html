2Cursor 절. 순서는 Orca와 같다: Cursor Models(Auto 등 Cursor 모델), Other Models(이름을 고른 모델), 플랜(포함 사용량 전체). 추가 사용량에 상한이 있으면 On-demand 줄이 Other Models 뒤에 생긴다. 결제 주기 끝 날을 「11월 20일에 초기화」로 보인다. 계정 목록 꺾쇠는 없다.

2. 규칙

항목규칙
계정그 위치(이 PC 또는 WSL 배포판)의 Cursor CLI 로그인 하나다. 이메일은 ~/.cursor/cli-config.json의 로그인 정보다.
사용량 출처Orca와 같다. CLI 로그인 토큰(~/.config/cursor/auth.json)으로 Cursor 대시보드의 /api/usage-summary를 읽는다. loom은 토큰을 읽기만 하고 갱신하지 않는다.
읽는 때Claude·Codex와 같다: 5분마다, 팝오버를 열 때, 새로 고침을 누를 때. 상한 15초.
로그인하지 않음상태 줄에 「로그인하면 보입니다」. Claude·Codex와 같은 문구다.
CLI가 없음「설치 안 됨」. 이 PC(Windows)에는 Cursor CLI가 없어 이 PC 저장소를 고르면 이 줄이 보인다.
토큰이 만료됨「이 계정으로 Cursor를 한 번 실행하면 갱신됩니다」.
보이지 않는 것팀 사용량. 상한이 없는 추가 사용량(이 계정의 On-demand는 상한이 없다). 요금제 이름(Enterprise 등)은 Claude·Codex처럼 보이지 않는다.
설정 › 계정바꾸지 않는다. Cursor 계정 추가·전환은 이번에 넣지 않는다.
폰폰 사용량 줄과 판에도 같은 Cursor 줄이 보인다(같은 부품).

3. Orca와 비교

항목OrcaM18 v2다른 점과 이유
창 이름Cursor Models · Other Models · On-demand · 플랜같다없음. 묶음 이름은 Orca도 번역하지 않는다
보이는 창두 묶음과 플랜. On-demand는 켜져 있고 비율이 있을 때만같다없음
팝오버 순서묶음 먼저, 플랜 마지막같다없음
상태 줄묶음만(이름과 %). 플랜은 상세 칸에만묶음만, 막대를 붙인다loom 상태 줄은 모든 창에 막대를 붙인다(목업 usage.html)
초기화 줄설정: 「11월 20일에 초기화」. 팝오버 머리: 가장 빠른 초기화까지 남은 시간창마다 남은 시간, 아래에 「11월 20일에 초기화」loom 팝오버는 창마다 남은 시간을 보인다(2026-10-20 사람 지시 “남은 리필시간도 표시해줘 orca처럼”)
머리 줄Cursor · Enterprise(공급자 이름과 요금제)로고와 이메일loom은 모든 공급자에 요금제 이름을 보이지 않고 계정 이메일을 보인다(docs/design/에이전트-실행.md 「넣지 않은 Orca 기능」)
공급자 순서가장 많이 쓴 공급자가 위Claude, Codex, Cursor 고정loom은 이 줄 세우기를 넣지 않았다(같은 절)
계정 전환없다(Claude·Codex만)없다없음

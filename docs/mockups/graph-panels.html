커밋 그래프

모든 브랜치 · 최근 1,000개

    그림 B. 도구 줄 [커밋 그래프]를 누르면 오른쪽 칸이 이벤트 콘솔에서 커밋 그래프로 바뀐다. 커밋·부모·참조는 시험 저장소의 실제 값이고, 차선은 아래 스크립트(VS Code 차선 계산을 옮긴 것)가 그렸다. 시간과 태그 v0.1은 보기 위해 바꾸거나 더했다. 폴더 그림이 붙은 브랜치 칩이 워크트리 묶음이 체크아웃한 커밋이다.

    바뀌는 곳

    위 그림은 바뀌는 구역만 그렸다. 지금 화면은 사이드바에 저장소 이름 한 줄, 가운데에 그래프, 아래에 상태 줄이 있다(캡처는 총괄 보고에 첨부). 이 문서는 왼쪽 영역을 「사이드바」, 그 안 목록을 「트리」라고 부른다.

    1. 사이드바: 저장소 목록 → 트리, 맨 아래 [설정]

    • 전 → 후: 저장소 이름·경로 한 줄 → 저장소 > 워크트리 묶음 > 노드 트리. 자식 노드는 부모 아래에 들여 쓴다. 줄마다 상태 점, 이름, 에이전트, 읽지 않은 메시지 수, 보관 메시지 수가 있다.
    • 문제점: 카드가 많으면 어느 워크트리에 어떤 에이전트가 있고 누가 누구의 자식인지 그래프를 돌아다니며 찾아야 한다.
    • 개선 사항: 줄을 누르면 그래프가 그 노드로 옮겨 가고 그 카드를 고른다(입력을 받는다). 줄 머리를 누르거나 ←→로 접고 편다. ↑↓로 줄을 옮긴다. 머리의 [모두 펼치기]가 접은 줄을 모두 편다.
    • 부모가 다른 묶음에 있으면 자식은 자기 묶음 아래에 두고 「← 부모 이름」을 작게 보인다(그림의 구현).
    • 사이드바 맨 아래 고정 줄에 [설정]을 둔다(Orca와 같은 자리). 누르면 지금 설정 창의 에이전트 탭이 열린다. 트리가 길어도 [설정]은 움직이지 않는다.
    • 지우는 진입점: 상태 줄 오른쪽 끝 [설정]. 같은 동작으로 가는 진입점을 하나로 둔다. 사용량 팝오버의 [계정 관리]는 계정 탭으로 바로 가는 다른 동작이라 둔다.

    2. 그래프 위 도구 줄

    • 전 → 후: 저장소 이름·경로 → 오른쪽 끝에 [이벤트]·[커밋 그래프]. 열린 쪽이 눌린 모양이다. 경로는 트리로 옮겨 도구 줄에서 지운다.
    • 문제점: 메시지 흐름과 커밋 이력을 보려면 터미널마다 들어가 봐야 한다.
    • 개선 사항: 한 번 눌러 오른쪽 칸을 열고, 다른 쪽을 누르면 바뀌고, 열린 쪽을 다시 누르면 닫는다.

    3. 오른쪽 칸 — 이벤트 콘솔(그림 A)

    • 전 → 후: 없다 → 노드·워크트리·메시지 이벤트가 최근 것부터 쌓인다. 새 이벤트는 실시간으로 위에 붙는다.
    • 문제점: 누가 누구에게 무엇을 보냈는지, 노드가 언제 끝났는지 한곳에서 볼 수 없다. 메시지는 간선이 3초 깜박이고 사라진다.
    • 개선 사항: 줄을 누르면 그 이벤트에 관여한 노드를 모두 강조하고 그 사이 간선도 강조한다. 나머지는 흐려진다. 그래프는 그 노드들이 다 보이게 맞춘다. 지운 노드는 그래프에 없어 줄에 흐린 이름만 보인다.
    • 강조 끄기: 그래프 빈 곳 누르기, 같은 줄 다시 누르기, Esc(포커스가 터미널 밖일 때. 터미널 안의 Esc는 터미널 앱이 쓴다).
    • 메시지 본문은 첫 줄만 보인다. 여러 줄이면 [펼치기]가 붙고 누르면 전부 보인다.
    • 거르기: 종류 칩(노드·워크트리·메시지)과 노드 이름 칸. 이름은 보낸 노드·받은 노드·대상 노드 가운데 하나만 맞으면 보인다.
    • 상태: 이벤트가 없으면 「아직 이벤트가 없다」, 거른 결과가 없으면 「맞는 이벤트가 없다」.

    4. 오른쪽 칸 — 커밋 그래프(그림 B)

    • 전 → 후: 없다 → 커밋마다 한 줄. 왼쪽에 차선 그래프(차선마다 색, 병합 곡선), 오른쪽에 브랜치·태그 칩, 제목, 작성자, 시간이 있다. 모든 브랜치를 보인다.
    • 워크트리 표시: 워크트리 묶음이 체크아웃한 브랜치 칩 앞에 폴더 그림을 붙인다. 칩에 마우스를 올리면 「워크트리 feat/minimap가 체크아웃한 커밋」처럼 종류와 브랜치를 보인다. 종류 글은 묶음 머리(원래 체크아웃·워크트리)와 같다. 분리된 HEAD 워크트리는 그 커밋에 폴더 그림이 붙은 HEAD 칩을 따로 단다.
    • 칩 색은 그 커밋 차선의 색이다. 태그 칩은 점선 테두리다.
    • 줄에 마우스를 올리면 전체 해시가 보인다. 줄을 눌러도 아무 일이 없다(읽기 전용, 커밋을 누르는 요구가 없다).
    • 문제점: 워크트리 묶음이 어느 커밋에 있는지, 병합이 어떻게 이어졌는지 화면에서 볼 수 없다.
    • 상태: 처음 읽는 동안 「읽는 중…」, 커밋이 없으면 「아직 커밋이 없다」, git이 실패하면 git 오류 문장을 빨간 글자로 보인다.

    점검 기록

    • impeccable detect: 경고 2건, 모두 고치지 않는다. 「Cramped padding」은 화면 틀 .app의 아래 테두리다(안쪽 글자가 없다). 「Flat type hierarchy」는 설명 영역의 제목 단계이고 화면 부분이 아니다.
    • WIG: 트리는 role="tree"·treeitem·aria-expanded·aria-current를 쓴다. 아이콘만 있는 단추에 aria-label이 있다. 도구 줄 단추는 aria-pressed로 열린 칸을 알린다. 펼친 이벤트 줄 안의 [접기] 단추가 단추 안에 들어가지 않게 바깥을 div role="button"으로 바꿨다. 거르기 입력에 aria-label이 있다. 커밋 목록은 ol에 aria-label을 달고, 차선 SVG는 aria-hidden이다. 사이드바 [설정]은 글자가 있는 단추다.
    • 데스크톱 1440폭에서 그림 A·B를 찍어 겹침·잘림이 없는 것을 봤다.

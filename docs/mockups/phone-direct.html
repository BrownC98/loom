휴대폰 직접 연결: Tailscale 없이 같은 Wi‑Fi에서

사람 지시: "앱 연동은 orca처럼 tailscail 독립적으로 구현하라, 지금은 의존성이 너무 강함". Orca는 PC가 LAN 주소에서 직접 듣고, QR에 PC 주소와 PC 열쇠를 넣고, 앱이 그 열쇠로 상대가 진짜 PC인지 확인한다. loom도 같게 한다: 데몬이 폰 전용 HTTPS 문을 LAN에 열고, QR에 그 인증서의 지문을 넣고, Android 앱은 지문이 같은 PC에만 붙는다. Tailscale은 고를 수 있는 길로 남는다. 점선이 바뀌는 곳이다.

① 연결 흐름 Serve 없이 · 앱이 인증서 지문을 확인한다

  • 폰 문은 데몬이 연 두 번째 문이다. PC 화면의 문(루프백)은 그대로다. 폰 문은 짝짓기 요청, 짝지은 기기의 요청만 받는다(지금 Serve로 온 요청과 같은 규칙).
  • 인증서는 데몬이 처음 한 번 만들어 데이터 폴더에 둔다. 같은 Wi‑Fi의 다른 기기가 가운데에 끼어도 지문이 달라 앱이 열지 않는다(Orca의 PC 열쇠 확인과 같다).
  • 공유기가 PC 주소를 바꾸면 앱이 닿지 않는다. 그때는 QR을 다시 찍는다(④).

브라우저(iPhone)로 쓰기 · 선택

Tailscale Serve 꺼짐
브라우저는 loom의 인증서를 확인하지 못합니다. iPhone·브라우저에서 쓰려면 Tailscale Serve를 켭니다. 그러면 QR이 https://…ts.net 주소도 담습니다.
  • 주소 줄은 데몬이 읽은 네트워크 주소다. 가상 어댑터(WSL, Hyper‑V, Docker)는 뺀다. Tailscale 주소(100.x)는 명령 없이 네트워크 주소에서 찾는다.
  • QR에는 코드 칸이 없다. 앱은 QR의 지문으로 PC를 확인하므로 코드만 적어서는 같은 Wi‑Fi로 짝짓지 않는다(결정 2).
  • [방화벽 허용]은 Windows 데몬에만 있다. Orca와 같게 loom.exe·폰 문 포트에 「개인 네트워크, 들어오는 TCP 허용」 규칙을 넣고, loom을 막는 규칙을 지운다.
  • 지금의 「Tailscale을 찾지 못했습니다」, 「Serve 꺼짐」 때문에 [휴대폰 연결]이 숨는 상태는 없어진다.

승인할 것

#정할 것안
1앱이 PC에 닿는 길A(권장): 데몬이 LAN에 폰 전용 HTTPS 문을 열고, 앱이 QR의 인증서 지문으로 PC를 확인한다. 화면 코드는 그대로 쓴다. / B: Orca처럼 앱 안에 암호 터널을 만든다(앱·데몬 양쪽 코드가 몇 배 크다).
2같은 Wi‑Fi에서 코드만 적어 짝짓기A(권장): 하지 않는다. 같은 Wi‑Fi는 QR로만 짝짓고, 코드 칸은 Tailscale Serve 주소에만 남긴다. / B: 주소와 코드를 적으면 처음 받은 인증서를 믿는다(같은 Wi‑Fi에 낀 기기를 막지 못한다).
3브라우저·iPhone 길(Tailscale Serve)A(권장): 「선택」 칸으로 남긴다. / B: 지운다. iPhone은 iOS 앱이 나올 때까지 쓰지 못한다(Tailscale 코드 약 300줄을 지운다).
4Windows 방화벽A(권장): [방화벽 허용] 단추(관리자 확인 창). / B: Windows가 처음 띄우는 허용 창에만 맡긴다(한 번 거절하면 사람이 직접 고친다).
5밖에서 쓰기A(권장): Tailscale이 있으면 tailnet 주소를 QR에 넣는다(Serve 없이). Relay는 만들지 않는다. / B: 같은 Wi‑Fi만 쓴다.

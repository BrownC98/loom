# 데스크톱 앱

Windows와 macOS(Apple Silicon)에서는 앱 하나(`app/`)로 loom 창을 연다(2026-10-19 사람 지시 "exe 로도 만들어서 윈도우에서 네이티브로 쓸 수 있게 해줘", 2026-10-21 사람 지시 "애플 실리콘, 디벨롭 계정 없음, 윈도우, 웹, 맥 버전의 코드 차이를 최소화 하는 방향으로 진행"). 두 OS가 같은 코드를 쓴다. OS마다 다른 곳은 앱 창 설정(`app/src/main.rs`), 화면의 `web/src/platform.ts`, 묶음 설정(`app/tauri.macos.conf.json`)뿐이다. 맥에서는 맥의 관례를 따른다(사람 결정 2026-10-21 "맥에선 맥의 법칙을 따르라"). 아래 표는 두 OS에 같고, 「macOS」 줄만 맥의 차이다.

| 결정 | 이유 |
|---|---|
| 창은 Tauri 2 앱(`app/`)이다. wry+tao를 직접 쓰지 않는다 | 한 번만 실행, 창 위치 기억, NSIS 설치 파일, WebView2 설치를 Tauri와 공식 플러그인이 맡는다. wry+tao로는 이 넷을 직접 만들어야 한다 |
| 앱은 옆에 놓인 `loom start`(Windows `loom.exe`, macOS `loom.app/Contents/MacOS/loom`)를 부르고, 첫 `loom: ` 줄의 주소를 창에 연다. 도는 데몬이 있으면 붙고, 없거나 옛 판이면 새로 띄운다(「데몬 하나」) | 노드가 부르는 `loom` 명령이 같은 실행 파일이다. 데몬 코드와 붙는 규칙은 `src/launch.rs` 한 곳이라 앱·`loom open`·`host.sh`가 같다. |
| 데몬은 앱과 따로 산다. 앱을 끝내거나 창을 닫아도 데몬과 노드는 돈다. 데몬만 끝내려면 `loom stop`이다 | 사람 결정(2026-10-21) "상태를 하나로 통일하고 프론트는 뷰어의 역할에 충실하게 한다". 브라우저 탭과 앱 창이 같은 데몬을 본다. 전의 `--until-stdin-closes`(앱이 끝나면 데몬도 끝남)는 지웠다 |
| 창을 닫아도 노드는 계속 돈다. 데몬도 살아 노드의 loom 명령(메시지, 훅)이 닿는다 | 사람 결정(2026-10-21, 총괄 경유) "Orca와 같게". Orca는 앱을 끝내도 터미널 데몬을 끝내지 않는다(`src/main/startup/main-process-quit.ts`의 `disconnectDaemon`) |
| 다시 띄운 데몬은 `daemon.json`의 포트에서 먼저 듣는다. 그 포트를 쓸 수 없으면 OS가 고른 포트로 띄운다 | 노드 환경의 `LOOM_URL`은 데몬 포트를 담는다. 새 포트로 띄우면 살아 있는 노드의 loom 명령이 닿지 않는다. 앱 설정 폴더의 `daemon-port` 파일은 지웠다 |
| 설치 파일은 `loom.exe`를 쓰기 전에 옛 `loom.exe`를 지운다. 지우지 못하면(도는 노드가 쓴다) 이름을 `loom.exe.<틱>.old`로 바꾼다. 앞 설치가 남긴 `.old`는 그때 지운다. 깔린 `loom.exe`가 설치 파일보다 새 판이면(`loom.exe --version`, `host.sh` 개발 빌드) 바꾸지 않고 둔다: 설치 전 훅이 `loom.exe.keep`으로 비켜 두고 설치 뒤 훅이 되돌린다. 끊긴 설치가 남긴 `.keep`은 설치 전 훅이 `loom.exe`와 비교해 새 판을 남긴다. 훅은 `app/windows/installer-hooks.nsh`다 | 도는 실행 파일은 덮어 쓰지도 지우지도 못하지만 이름은 바꿀 수 있다(「실측 근거」). 도는 PTY 호스트는 이름을 바꾼 옛 파일을 계속 쓴다. Linux `host.sh`의 rename과 같은 방법이다. 새 판을 두는 것은 「새 판이 이긴다」를 파일에도 지키기 위해서다. 2026-10-22 앱 업데이트(0.1.716)가 개발 빌드(0.1.899)를 옛 판으로 바꿨다. Orca는 데몬을 `%LOCALAPPDATA%`에 복사해 띄운다. 그 방법은 데몬 복사본 관리가 더 든다 |
| 앱 지우기는 이 설치 폴더의 `loom.exe`로 도는 프로세스(데몬, PTY 호스트)와 그 자손을 끝내고 `.old` 파일을 지운다. 프로세스는 경로로 고른다 | 지우기 뒤에 노드가 남지 않는다. 이름(`taskkill /IM`)으로 고르면 다른 폴더의 `loom.exe`도 끝낸다. 업데이트는 지우기를 부르지 않는다(아래 「이전 판」 줄) |
| 데몬은 콘솔 창 없이(`CREATE_NO_WINDOW`) 띄운다 | 데몬이 띄우는 콘솔 프로그램도 그 숨은 콘솔을 물려받아 새 창을 열지 않는다 |
| 데몬의 시작 폴더는 앱 설정 폴더다. 폴더 고르기 창은 없다. 저장소는 화면의 [+]로 더하고, DB에 남아 다음 실행에도 보인다 | 저장소 목록이 DB에 있어 앱이 마지막 폴더를 따로 기억할 요구가 없다. 화면의 저장소 추가 창(기존 폴더, URL 복제, 새 프로젝트)이 고르기 창의 일을 한다 |
| 설치가 끝나면 설치 프로그램이 마지막 화면(바로 실행, 바탕 화면 바로 가기)으로 바로 넘어간다. 훅 파일 `app/windows/installer-hooks.nsh`가 `SetAutoClose true`를 부른다 | 사람 지시(2026-10-20) "설치 완료시 바로 설치 프로그램 마지막 화면으로 이동하게 해줘". Tauri 템플릿은 설치 기록을 보이려고 설치 화면에 머문다. 템플릿을 복사하지 않고 Tauri가 주는 설치 후 훅만 쓴다 |
| 이전 판이 깔려 있으면 묻지 않고 같은 폴더에 덮어 설치한다. 릴리스 빌드가 그 Tauri CLI 판의 설치 템플릿을 받아, 이전 설치를 찾는 줄 하나를 `Abort`로 바꾼다. 그 줄이 없으면 빌드가 실패한다 | 사람 지시(2026-10-21) "새버전 설치시 이전버전 삭제, 새버전 설치가 한큐에 진행되도록". 템플릿은 「먼저 지우기/지우지 않기」 화면과 옛 판의 제거 마법사를 띄운다. 앱 업데이트(`/UPDATE`)도 지우지 않고 덮어 쓴다. 데이터 폴더는 어느 쪽도 지우지 않는다 |
| 한 번만 실행한다. 두 번째 실행은 있는 창을 앞으로 가져온다 | Orca와 같다 |
| 창 위치·크기를 기억한다(`tauri-plugin-window-state`) | Orca와 같다 |
| 창에는 OS 제목 줄이 없다(`decorations(false)`). 화면이 앱에서만 맨 위에 36px 줄을 그린다: 왼쪽 loom 마크, 빈 곳 끌기·두 번 눌러 최대화, 오른쪽 최소화·최대화·닫기([titlebar.html](../mockups/titlebar.html), `web/src/TitleBar.tsx`). 권한(`app/capabilities/window.json`)은 끌기·최대화 상태 읽기·최소화·최대화·닫기뿐이다. 창 상태 플러그인은 제목 줄 여부를 저장하지 않는다. Windows 11 스냅 레이아웃 팝업(최대화 버튼에 마우스)은 없다. Win+Z와 가장자리로 끌기 스냅은 된다 | 사람 지시(2026-10-21) "orca 처럼 상단 앱바를 기본 ui 말고 세련되게 할 수 없나". 줄이 loom 테마(라이트·다크)를 따른다. 팝업을 살리는 플러그인(`tauri-plugin-decorum`)은 의존성이 늘어 넣지 않았다(사람 승인, 목업 M5). 판 번호는 상태 줄에, 이름은 사이드바 머리에 있어 줄에 두지 않는다 |
| macOS: 앱은 사람의 셸(`$SHELL -ilc`)에서 `PATH`를 한 번 읽어 데몬에 준다. 읽지 못하면 받은 `PATH`를 쓴다. 데몬은 에이전트를 찾을 때 셸을 다시 읽는다(「에이전트」 탐지). 앱의 읽기는 찾기 `PATH`를 쓰지 않는 데몬 명령(`git`, 병합 관문 `check.sh`·`ship.sh`)을 위해 남긴다 | Finder·Dock에서 띄운 앱은 로그인 셸의 `PATH`를 받지 않는다(`/usr/bin:/bin:/usr/sbin:/sbin`). 그러면 `~/.local/bin`·Homebrew의 `claude`·`codex`를 찾지 못한다. `-i`는 `~/.zshrc`에 `PATH`를 더한 설치(Claude Code 안내)도 읽기 위해서다. Windows 앱은 사용자 `PATH`를 받는다 |
| macOS: 창 맨 위는 OS가 왼쪽에 창 버튼(신호등)만 그리고(`titleBarStyle: Overlay`, 제목 숨김), 화면이 같은 36px 줄을 그린다. 줄은 왼쪽 64px을 비우고 오른쪽 창 버튼을 그리지 않는다([mac-titlebar.html](../mockups/mac-titlebar.html) 안 B) | 사람 결정(2026-10-21) "맥에선 맥의 법칙을 따르라". 줄 색·높이·마크는 Windows와 같다 |
| macOS: 창을 닫으면 앱은 끝나지 않고 창만 숨긴다. Dock 아이콘을 누르면 다시 보인다. ⌘Q가 앱을 끝낸다. 데몬은 산다. 메뉴 막대는 Tauri 기본 메뉴(앱·편집·창)다 | 맥 관례다. 편집 메뉴가 있어야 화면에서 ⌘C·⌘V가 된다 |
| 화면의 단축키는 명령 키+Shift다. 명령 키는 macOS에서 ⌘, 다른 OS에서 Ctrl이다. 터미널의 복사·붙여넣기도 명령 키다(macOS ⌘C·⌘V, 다른 OS Ctrl+C·Ctrl+V). macOS 터미널의 Ctrl+C는 늘 `^C`다. 판별은 `web/src/platform.ts` 한 곳이다. 브라우저 화면도 같다 | 맥 관례다. 툴팁과 `aria-keyshortcuts`가 OS에 맞는 키(`⌘⇧F` 등)를 보인다 |
| macOS: 앱은 Apple 개발자 서명과 공증 없이 낸다. 묶음은 ad-hoc 서명(`signingIdentity: "-"`)이다. 사람은 터미널 한 줄(`curl … install.sh \| sh`)로 설치한다. `install.sh`는 Apple Silicon만 받는다. `latest.json`의 판으로 `loom_<판>_aarch64.app.tar.gz`를 `/Applications`(쓸 수 없으면 `~/Applications`) 안 임시 폴더에 받아 풀고, `xattr -cr`을 하고, 이 사용자의 도는 앱(`loom-app`)을 `pkill`(SIGTERM)로 끝내고(10초 안에 끝나지 않으면 멈춘다), 옛 `loom.app`을 새 묶음으로 바꾸고 `open`한다. 새 묶음을 넣지 못하면 옛 묶음을 되돌린다. 데몬은 끝내지 않는다. 새 앱의 `loom start`가 새 판이 이겨 데몬을 바꾼다. 데이터(`~/.loom`)는 그대로다. 다시 부르면 업데이트다. 터미널 없이는 `.dmg`에서 앱을 응용 프로그램 폴더로 끌고, 처음 한 번 `xattr -cr /Applications/loom.app`을 실행한다 | 사람 결정(2026-10-21) "디벨롭 계정 없음". 브라우저로 받은 서명 없는 앱은 Gatekeeper가 「손상되었기 때문에 열 수 없습니다」로 막는다. `xattr`가 받은 파일 표시(`com.apple.quarantine`)를 지운다. curl로 받은 파일에는 이 표시가 붙지 않는다. Apple Silicon은 서명 없는 실행 파일을 띄우지 않아 ad-hoc 서명은 둔다. 한 줄 설치는 사람 결정(2026-10-24, Q818 A, 피드백 "맥 os 사용자가 설치가 어렵다"). 앱을 끝내지 않으면 `open`이 도는 옛 앱을 앞으로 가져오기만 한다. 끝내기에 Apple 이벤트(`osascript … quit`)를 쓰지 않는다: 터미널이 앱을 제어하는 권한을 물을 수 있고, 답하지 않는 앱에는 2분까지 기다린다. 시험(2026-10-24, GitHub Actions `macos-14`, macOS 14.8.9, Gatekeeper 켬, 버리는 워크플로): 0.1.1465를 설치해 앱과 데몬이 떴다. 앱이 도는 채로 다시 불러 0.1.1472로 바꿨다. 앱 프로세스가 바뀌고 데몬 판이 0.1.1472가 되고 창이 떴다. `codesign --verify --deep --strict`는 통과, `spctl --assess`는 거절(ad-hoc)이지만 받은 파일 표시가 없어 앱이 떴다. 둘째 시험(같은 조건): 웹 버전 0.1.1465 데몬이 도는 Mac에서 한 줄을 부르자 데몬이 앱의 loom(0.1.1465)으로 바뀌고 `~/loom/bin/loom`이 껍데기가 됐다. 이어 0.1.1472로 바꿀 때 `pkill`로 앱이 끝났고(프로세스가 바뀜) 옛 `loom.command`가 앱의 데몬을 열었다 |
| macOS 업데이트: Tauri 업데이터가 `.app.tar.gz`를 받아 서명(`.sig`, Windows와 같은 키)을 확인하고 앱 묶음을 바꾼다. 그 뒤 화면이 앱을 다시 띄운다(`tauri-plugin-process`의 `relaunch`, 권한 `process:allow-restart`). Windows는 설치 파일이 앱을 끝내 `relaunch`에 닿지 않는다 | 업데이터는 Apple 서명을 보지 않는다. 받은 파일은 메모리에서 풀어 쓰므로 받은 파일 표시가 붙지 않는다(`tauri-plugin-updater` 2.13.1 소스). 그래서 업데이트 뒤에 `xattr`를 다시 하지 않는다 |
| macOS에서 다른 것(고치지 않는다): 노드 문(`127.76.77.1`)을 듣지 못해 Codex 노드는 loom 명령마다 승인을 묻는다(「실측 근거」의 macOS). 고치려면 루트 권한으로 `lo0`에 주소를 더해야 한다. Claude Code는 로그인을 키체인에 두어 `.credentials.json`이 없다. loom은 Claude 사용량 토큰만 키체인에서 읽는다(「계정과 사용량」 표). 로그인과 손으로 하는 계정 전환은 CLI가 `CLAUDE_CONFIG_DIR`마다 키체인을 따로 쓰므로 loom 코드가 필요 없다(Orca 소스 `claude-auth-capture.ts`). 저장소가 문서·데스크탑·다운로드 폴더에 있으면 macOS가 처음 한 번 폴더 접근을 묻는다 | 키체인 읽기: 새로 가입한 macOS 사용자의 Claude 사용량이 「이 로그인 방식(API 키 등)은 사용량을 볼 수 없습니다.」였다(2026-10-24 사람 "다른사용자가 클로드를 새로 가입했는데 해당 경우에는 클로드 사용량이 안보임", Q815 macOS). 총괄 브리프가 읽기 전용 키체인 읽기를 지시했다. Cursor 키체인은 범위 밖이다 |

# o-mode 참고

[o-mode](SKILL.md)에서 드물게 쓰는 절차다. 그 일을 할 때 이 파일을 읽는다.

## 설치 판

- 설치된 `loom --help`, `loom spawn --help`, `loom wait --help`를 읽는다. 소스에 있는 기능을 설치된 기능으로 간주하지 않는다.
- `status`, `note`, `answer`, `wait --reply-to --timeout --json`의 지원 여부를 확인한다. 없으면 그 기능이 필요한 위임을 보류하고 직접 작업한다. 버전 차이를 보고한다. 사용자 데몬을 임의로 교체하지 않는다.
- 모델·강도 옵션은 설치된 `loom spawn --help`에 있을 때만 쓴다. 없으면 사용자 설정을 따르며 실제 모델을 보고한다. 임의의 셸 명령으로 에이전트를 띄워 프로필을 우회하지 않는다.

## 명령

| 목적 | 명령·동작 |
|---|---|
| 인계 | 새 총괄에서 `loom adopt <코디 이름>`. 현재 관계와 보관된 메시지를 확인한다 |
| 조치 전파 | 살아 있는 자식마다 `loom note`. 코디는 필요한 조치를 자기 자식에게 전달한다 |
| 실패 후 재배정 | 기존 노드의 종료를 확인하고 새 이름으로 생성한다. 브리프에 보존한 브랜치·결과를 적는다 |

`--worktree` 자식은 부모의 커밋된 `HEAD`로 저장소 설정 스크립트를 돌린다. 그래서 설정(빌드 포함)이 통과하는 `HEAD`를 커밋한 뒤 띄운다. 부모가 `setup failed (exit <코드>): <출력 끝>`을 받으면 그 출력으로 원인을 고치고 커밋한다. 그 뒤 실패한 자식을 `loom rm`으로 지우고, 그 워크트리와 브랜치를 `git worktree remove`·`git branch -d`로 지운 뒤 같은 이름으로 다시 띄운다.

## 막힘

- 같은 완료 명령이 두 번 실패하거나 환경 문제로 10분 넘게 막히면 부모에게 원인·영향·시도·필요한 결정을 보낸다.
- 부모는 해결 담당자와 조치를 정한다. 관련 자식에게 원래 메시지 번호와 함께 알리고 해결 결과를 확인한다.

## 질문·응답과 대기

- 시작할 때와 `adopted` 알림 뒤에 `loom status`로 현재 부모와 자식을 확인한다. 전송이 실패해도 관계와 `alive`를 먼저 확인한다. 메시지는 먼저 현재 부모와 자식에게 보내고, 보고는 부모에게 한다. 다른 노드에는 이름이나 `loom status --all`의 번호로 보낸다. 조정·중단은 현재 부모와 자식 사이에만 보낸다.
- 질문은 `loom ask <질문>`으로 부모에게 보낸다. 출력의 메시지 번호를 기록한다. 노드 번호와 메시지 번호를 구별한다. 자식에게 묻는 일은 `loom note`로 보내고 `loom done`이나 답을 받는다.
- 받은 질문(`kind: ask`)에는 `loom answer <메시지 번호> <본문>`으로 답한다. 답변에는 원래 질문 번호가 붙는다. 부모가 바뀌어 답변이 거절되면 현재 부모에게 질문 경위와 결과를 보낸다.
- 특정 답변은 `loom wait --reply-to <질문 번호> --timeout <초> --json`으로 확인한다. 자신이 보낸 질문 번호를 쓴다. 시간은 작업 예산 안에서 정한다. 이 대기는 다른 메시지를 소비하지 않는다. 훅이 이미 받은 답변도 찾는다.
- 제한 시간이 지나도 질문은 취소되지 않는다. 같은 질문을 자동으로 다시 보내지 않는다. 관계와 생존을 확인하고 감독 절차를 따른다. 늦은 답변도 원래 질문 번호로 확인한다.
- 모든 메시지는 메시지 번호로 중복을 걸러낸다(같은 질문을 다시 기다리면 첫 답변이 다시 나온다).
- 답변과 무관한 일은 계속한다. 기다려야 하면 턴을 끝낸다. 메시지가 오면 데몬이 쉬는 노드를 깨운다(Claude는 비동기 훅. Codex·OpenCode 2는 새 턴. Cursor는 stop 훅의 새 턴). 무기한 `loom wait`를 띄우지 않는다. 특정 답변을 명시적으로 확인할 때만 제한 시간 있는 대기를 쓴다.
- `done`은 작업 완료이며 프로세스 종료가 아니다. `alive: true`인 완료 노드는 피드백을 받는다. 완료 뒤에도 피드백을 기다리면 실행자별 수신 방식을 유지한다. `alive: false`인 노드는 새 이름으로 다시 띄운다.
- 완료한 노드가 메시지나 사람 입력을 받으면 다시 「실행 중」이 된다. 재작업을 끝내면 `loom done`을 다시 부른다.
- 메시지 본문은 4,096바이트 이하, 완료 요약은 1,024바이트 이하다. 긴 자료는 파일에 쓰고 경로를 보낸다. `done --file`은 파일 내용 대신 절대 경로를 보낸다. 결과 파일 자체에 메시지 본문 크기 제한을 적용하지 않는다.

## 사용자 보고서

- HTML 보고서는 사람이 명시해 요청할 때만 user-doc 형식으로 만든다. 총괄이 검수하고 `show.sh`로 점검한 뒤 `loom ask --doc`으로 붙인다(사람의 브라우저를 열지 않는다). 채팅·`loom done`에는 요약과 링크만 적는다.
- 에이전트끼리 읽는 글은 영어 markdown이다.

## 회수

- 미보존 변경, 검증·승인·병합 대기, 사용 중인 사용자 노드와 기준 체크아웃을 보존한다.
- 회수 전에 해당 워크트리의 `git status --short`로 미커밋 변경과 추적하지 않는 파일을 확인한다. 검토 증거가 그 폴더에만 있으면 먼저 보존한다. 다른 작업이 사용 중이면 회수하지 않는다.
- 노드는 `loom rm <자식 이름 또는 번호>`로 지운다. 자기 자식만 지울 수 있다. 그 자식의 프로세스도 끝난다.
- 지운 자식에게 자식(손자)이 있으면 손자는 내 자식이 된다. 그 노드도 결과를 보존한 뒤 `loom rm`으로 회수한다.
- 노드를 지운 뒤 기준 체크아웃에서 `git worktree remove <경로>`를 실행한다. 병합된 작업 브랜치는 `git branch -d <브랜치>`로 지운다. 강제 삭제하지 않는다.
- 남겨야 하는 워크트리는 경로·이유·담당자·회수 조건을 완료 보고에 적는다. 완료 상태라는 이유만으로 방치하지 않는다.
- 완료 보고 전에 `git worktree list`, `git branch`, 가능한 경우 `loom status`로 회수를 확인한다. 삭제 명령 실행만으로 완료했다고 보고하지 않는다.

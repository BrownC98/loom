# 저장

- SQLite 파일 하나: `<데이터 폴더>/loom.db`, WAL 모드. 데이터 폴더는 `~/.loom`이고, Windows는 앱 설정 관례대로 `%APPDATA%\loom`이다. 라이브러리는 `rusqlite`다.
- 사람이 받은편지함에서 답한 질문 번호는 `answers` 표에 남는다(마이그레이션 36). 답한 질문은 `questions`에서 지워지고 이벤트는 1만 개만 남기 때문이다. 주석 검사(`tests/comments`)가 `POST /api/agent/question`으로 묻는다(AGENTS.md 4절).
- 메시지의 `reply_to`(`loom wait --reply-to`가 찾는 색인)와 노드의 프로세스 결과(`nodes.process`)도 같은 DB에 둔다. 답이 가리키는 질문은 터미널 머리의 `question:` 칸(`MessageKind::Answer`)이 하나뿐인 출처다. `Delivery`에는 `reply_to`를 싣지 않는다(두 출처가 어긋나지 않게). 옛 거절 코드(`gateWord`, `hasParent`)는 이벤트 기록에서 마이그레이션 35가, 없앤 `loom merge`의 값(동사 `merge`, 종류 `merging`, 거절 코드)은 38이 새 꼴로 옮긴다. 프로세스 종료와 메시지 알림은 같은 트랜잭션에서 적는다.
- 메일함, 노드 목록, 저장소 목록, 카드 위치, 설정, 이벤트 기록을 모두 여기에 둔다. 워크트리 묶음은 git이 갖는다(「저장소와 워크트리」). 데몬이 다시 시작해도 메시지는 남는다.
- 데몬은 DB 연결 하나를 연다. 그래프, 저장소, 설정, 카드 자리가 그 연결과 잠금 하나를 나눠 쓴다. 그래서 데몬 안에서는 SQLite 잠금을 다투지 않고 `database is locked`가 나지 않는다. 연결이 넷일 때는 바쁜 WSL에서 커밋이 20~120 ms 걸렸다. 그동안 쓰기를 기다리는 연결은 잠깐 자고 다시 보기를 되풀이하다 계속 놓쳤고, 5초 뒤 실패했다(2026-10-22 사람 데몬의 `loom send`·응답 대기 지우기. 0.1.844 시험 데몬에서 30초에 15번, 연결 하나로 0번).
- 잠금을 쥔 채 다른 모듈의 DB 함수를 부르지 않는다. 같은 잠금을 다시 잡아 멈춘다.
- 트랜잭션은 시작할 때 쓰기 잠금을 잡는다(IMMEDIATE). 기본(DEFERRED)은 읽은 뒤 다른 프로세스가 커밋하면 첫 쓰기가 기다리지 않고 `database is locked`로 실패했다(2026-10-22 사람 데몬의 [답하기]·`loom spawn`).
- 다른 프로세스는 읽기 전용(`file:…/loom.db?mode=ro`)으로 읽는다. WAL에서 읽기는 데몬의 쓰기를 막지 않는다(`backup()` 반복 읽기와 함께 쓰기 시험에서 실패 0번).
- 잠금을 쥔 채 프로세스를 띄우지 않는다. 노드 줄과 토큰을 먼저 커밋하고, 띄운 뒤 화면에 보인다. 띄우지 못하면 줄을 지운다. 띄우기가 1초를 넘는 동안 [확인]·설정 저장 같은 요청이 모두 기다렸다.
- 이벤트 기록은 바꾼 트랜잭션 안에서 함께 쓴다. 되돌린 변경은 기록에 남지 않는다. 메시지 본문은 복사하지 않고 메시지 id로 가리킨다. 최근 10,000개만 남긴다.
- 계정 로그인 폴더는 같은 폴더의 `accounts/`에, 배포판 호스트 주소 파일(`distros/`)과 잠든 노드의 남긴 화면(`nodes.screens/`)은 `pty/`에 둔다. 노드 PTY 호스트의 주소는 DB `node_hosts`에 둔다(「에이전트 실행」).
- 터미널에 붙여넣은 그림과 끌어다 놓은 파일은 OS 임시 폴더의 `loom-paste/<번호>/`에 원래 이름으로 쓰고, 화면이 그 경로를 터미널에 붙여넣는다. 에이전트 CLI는 경로로 파일을 읽거나 그림을 첨부한다. 그림은 브라우저 클립보드에 있으므로 노드 기계의 클립보드 도구를 쓰지 않는다. 끌어다 놓은 파일도 데몬에 올린다. 브라우저는 원래 경로를 알려 주지 않고, WSL 노드는 Windows 앱이 아는 `C:\` 경로를 읽지 못한다(목업 [docs/mockups/terminal-drop.html](../mockups/terminal-drop.html) v1, 2026-10-21 사람 승인). 놓은 경로는 작은따옴표로 묶고 엔터는 누르지 않는다. 파일마다 32MB까지 받고 폴더는 받지 않는다. 지우기는 OS에 맡긴다. Windows 데몬의 WSL 노드 터미널이면 그 배포판의 `/tmp/loom-paste/<번호>/`에 쓰고 배포판 안의 경로를 붙여넣는다(화면이 노드 번호를 함께 보낸다). 질문 답에 붙인 그림도 같다.
- 터미널 링크(OSC 8)를 누르면 연다(2026-10-20 사람 지시 "loom 터미널에선 링크 클릭이 안되는 문제"). `http(s)`는 브라우저 새 탭이다. `file://`은 브라우저 페이지가 열지 못하므로 데몬이 그 기계의 기본 앱으로 연다(WSL은 `wslpath -w` 뒤 `explorer.exe`, Windows는 `explorer`, macOS는 `open`, 그 밖은 `xdg-open`). WSL 노드 터미널의 링크(`file:///home/…`)는 그 배포판의 UNC 경로로 연다. 데몬 PC 밖의 화면(폰 앱, 폰 브라우저: 루프백이 아닌 주소로 연 화면)은 PC의 기본 앱을 볼 수 없으므로 `file://`을 화면 안에서 연다: 데몬이 `/api/files/view/<노드|->/<경로>`로 그 파일을 낸다. 주소가 경로라 HTML 옆 그림도 열린다(2026-10-23 사람 "웹버전에서도 html을 브라우저로 볼수있게 해줘", "웹 말고 앱"). 그 화면은 이미 PC 터미널을 쓰므로 읽을 수 있는 파일이 늘지 않는다. 없는 경로는 열지 않는다. 폰 앱은 그 파일을 폰 브라우저(Chrome)로 연다. 앱의 WebView는 줌이 되지 않는다(2026-10-23 사람 "헤드리스 브라우저고 줌인아웃도 안됨 크롬이나 기타 모바일 웹브라우저에서 볼수없나"). 폰 브라우저에는 기기 쿠키가 없으므로 앱 화면이 통행증(`POST /api/files/pass`)을 받는다. 통행증 주소 `/api/files/pass/<토큰>/<파일>`은 쿠키 없이 그 파일의 폴더 아래만 30분 읽는다(`src/daemon/passes.rs`). Serve가 켜져 있으면 tailnet 이름으로 준다. 폰 문은 스스로 서명한 인증서라 브라우저가 경고한다. 화면은 이 주소를 `window.open`이 아니라 앱의 다리(`loomBrowser.open`)로 넘긴다. `window.open`은 앱 WebView 안에 열렸다(2026-10-23 사람 "여전히 헤드리스 브라우저임"). 다리는 통행증 주소만 폰 기본 브라우저로 연다. 다리가 없는 옛 APK는 화면 안에서 연다. 다른 형식은 열지 않는다. 캔버스 배율과 관계없이 누른 칸을 고른다("터미널 링크가 화면이 클때만 작동함"): xterm은 CSS `scale`을 빼지 않으므로 마우스 위치를 배율 1로 되돌려 넘긴다.

git 없는 폴더에서 loom 쓰기

사람 지시: 「loom이 git 없는 폴더에서도 작업할 수 있게 기획 구현해줘」. 지금 loom은 git 저장소가 아닌 폴더를 거절합니다. 바뀐 뒤에는 그 폴더를 그대로 더하고, 노드가 그 폴더에서 일합니다. git이 하던 일(워크트리, 검사, 병합)은 그 폴더에서 쓰지 않습니다.

[+]로 git 없는 폴더를 더한다→그 폴더에 노드를 띄운다→자식 노드도 같은 폴더에서 일한다→끝나면 loom done으로 보고한다

D1git 없는 폴더를 더할 때 git을 만들지 묻는가

A묻지 않고 그대로 더한다권장지금: 오류로 거절 → 바뀐 뒤: 바로 더함 · 폴더를 건드리지 않음 · 되돌리기: [목록에서 빼기]
B「git 만들고 더하기」와 「그대로 더하기」를 고르게 한다지금: 오류로 거절 → 바뀐 뒤: 창 하나를 더 거침 · git을 만들면 폴더에 .git이 생김 · 되돌리기: .git을 손으로 지움
  • 사람의 폴더에 몰래 파일을 만들지 않습니다.
  • git이 필요해지면 터미널에서 git init을 하면 됩니다. loom이 다음 새로 고침에서 git 저장소로 봅니다.

D2git 없는 폴더에서 자식 노드는 어디서 일하는가

A부모와 같은 폴더에서 일한다권장지금: 폴더를 더할 수 없음 → 바뀐 뒤: 총괄이 자식에게 서로 다른 파일을 맡김 · 위험: 두 노드가 같은 파일을 고치면 나중 것이 덮어씀 · 되돌리기: 없음(git이 없어 기록이 없음)
B자식 노드를 막는다바뀐 뒤: 노드 하나만 그 폴더에서 일함 · 덮어쓸 위험 없음 · 조사·검토를 나누지 못함
C자식마다 폴더 사본에서 일하고 끝나면 loom이 합친다바뀐 뒤: git 없이 병합을 흉내 냄 · 새 부품이 많고 충돌을 풀 방법이 없음 · 큰 폴더는 사본이 느림
  • 파일을 고치지 않는 일(조사, 요약, 검토)은 같은 폴더에서 나누어도 안전합니다.
  • 나누어 고치고 합쳐야 하는 일은 git이 하는 일입니다. 그때는 git init을 씁니다.
  • 노드 지시문에 「git 없는 폴더에서는 자식에게 서로 다른 파일을 맡긴다」를 넣습니다.

③ 노드가 git이 필요한 명령을 쓰면: 할 일을 알려 주고 거절한다 「회의록 총괄」의 터미널

$ loom check
/home/me/문서/회의록 has no git, so loom has no branch, check or merge gate here.
Your edits in this folder are the result: report it with loom done.
7부모 없는 노드도 --worktree 없이 자식을 띄운다.
8--worktree는 거절한다. 지금은 git의 오류 글이 그대로 나온다.
9loom check와 loom ready도 같은 방법으로 거절한다. 결과는 loom done으로 보고한다.

바뀌지 않는 것

  • git 저장소는 지금과 똑같이 움직입니다.
  • 데몬을 git 없는 폴더에서 띄워도 그 폴더를 스스로 더하지 않습니다. 사람이 [+]로 더합니다.
  • 폴더에서 git init을 하면 loom이 그 뒤로 git 저장소로 봅니다. 다시 더할 필요가 없습니다.
  • 질문, 답, 알림, 완료 보고(loom ask, done, note)는 git과 관계없이 됩니다.

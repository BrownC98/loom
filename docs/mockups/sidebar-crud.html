사이드바 줄에서 저장소·워크트리·노드 만들기·고치기·지우기

사용자 요청(2026-10-20): "사이드바의 요소들을 crud 가능하게 만들어". 지금 사이드바는 저장소 더하기([+])와 노드 이름 바꾸기(두 번 누르기, F2)만 한다. 나머지는 그래프에만 있다. 그래프의 팝오버를 그대로 다시 쓴다. 새 창을 만들지 않는다.

1. 동작을 어디에 보일까

같은 장면을 두 안으로 그렸다. 폭은 기본 260px다. 마우스는 각 그림에서 한 줄에 있다.

2. A안: 줄 종류마다 단추

왼쪽 셋은 마우스를 올린 줄이 다르다. 넷째는 최소 폭 180px에서 키보드 포커스가 노드 줄에 있다.

3. 팝오버와 거절

팝오버는 누른 줄 오른쪽, 사이드바 경계 밖에 붙는다. 내용은 그래프의 팝오버와 같다.

4. 결정할 것과 권장

질문권장이유
동작 자리A. 줄 끝 단추(마우스·포커스 때) + Delete 키사이드바에서 바로 보인다. 우클릭 메뉴는 새 부품이 크고 찾기 어렵다.
저장소 고치기없음이름은 폴더 이름이고 경로는 저장소의 정체다. 고칠 값이 없다. 다른 경로면 빼고 다시 더한다.
저장소 지우기「목록에서 빼기」: repos 줄만 지운다. 폴더는 지우지 않는다. 그 저장소에 노드가 있으면 거절한다사람의 파일을 잃지 않는다. 노드를 같이 지우면 보관 메시지를 잃는다. 데몬 시작 폴더 저장소는 다음 시작 때 다시 더해진다(지금 규칙).
워크트리 만들기저장소 줄 [새 워크트리]. 도구 줄 단추는 그대로 둔다사이드바 CRUD 요청이다. 같은 팝오버라 새 부품은 단추 하나다.
워크트리 고치기없음브랜치 이름을 바꿔도 폴더 경로는 그대로라 이름과 폴더가 어긋난다. 노드는 폴더 경로를 가리킨다. 터미널의 git branch -m은 5초 안에 사이드바에 보인다.
노드 만들기워크트리 줄에서만. 그 묶음의 뿌리 노드사람이 띄운 노드는 늘 뿌리다(지금 규칙). 자식으로 띄우려면 NewNode에 부모가 생기고 데몬 규칙이 바뀐다. 필요하면 띄운 뒤 그래프에서 끌어 입양한다.
노드 고치기이름만(단추 + F2). 부모 바꾸기는 그래프 끌기 그대로사이드바에서 끌어 입양하는 부품은 크다. 요청이 오면 따로 한다.
노드 지우기단추 + Delete. 확인 없이 바로 지운다카드와 같은 규칙(2026-10-20 사람 지시 「노드 제거시 경고 팝업 안뜨고 바로 삭제」).

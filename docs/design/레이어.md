# 레이어

기능 역할로 나눈다. 의존은 위에서 아래로만 둔다. 기능 모듈끼리는 서로 부르지 않는다.

상호작용 레이어에는 아래 Rust 모듈 말고 화면(`web/`), 데스크톱 앱 창(`app/`), 폰 앱(`android/`)도 있다. `tests/layers`가 `cargo test --test layers`(Linux)에서 아래 세 표를 읽고 `src/`의 `crate::` 경로와 `use`를 검사한다. `use` 별칭과 다시 내보내기는 항목의 주인까지 따라가고, `include!`한 파일과 `#[path]` 모듈도 읽는다. `test`를 반드시 요구하는 `cfg` 코드만 뺀다. 표에 없는 모듈, 위로 가는 의존, 기능 모듈끼리의 호출(값 타입 표의 타입만 된다), 모듈 순환이 있으면 실패한다. 예외 표에 있는 의존만 통과한다.

예외 표는 아직 고치지 않은 위반이다. 검사는 표의 항목을 통과시키고 순환 검사에서도 뺀다. 고친 항목이 표에 남으면 실패하므로 표는 줄기만 한다.

| 의존 | 항목 | 고칠 방법 |
|---|---|---|

- `Profile`은 메시지 연동이고 `Provider`는 계정이다. OpenCode 2와 Cursor는 프로필은 있고 공급자는 없다. Cursor 노드는 Cursor CLI의 로그인을 쓴다.
- 에이전트마다의 계정·사용량 지식은 그 어댑터에만 있다. 어댑터는 `Facts.logins`로 알린다: 없음, 위치마다 로그인 하나와 사용량 읽기(`One`), 계정 여럿과 CLI 사실과 사용량 읽기(`Many`). `accounts`·`usage`·데몬은 에이전트 이름을 모른다. 계정이 있는 에이전트를 더하면 그 어댑터와 `Provider` 변형 하나를 더한다.
- 프로필 어댑터는 그래프를 모른다. 훅 사건(`profile::HookEvent`)은 사건을 읽고 답을 쓰기만 한다. 데몬 안에서 도는 어댑터 작업은 포트(`profile::adapter::Port`)만 부른다. 포트의 요청·응답 타입은 기반 층(`protocol::link`)에 있다. 메일함은 데몬 코어(`daemon::agent`)만 본다. 데몬 코어는 에이전트 이름도, 훅·서버 같은 에이전트 분류도 모른다.
- 그래프도 프로필을 모른다. 데몬이 `Graph::open`에 메시지 연동이 있는지 묻는 함수(`profile::linked`)를 넘긴다.
- 노드 호스트는 키에 대해 제네릭이다. 노드 PTY(`NodeId`)와 로그인 창 PTY(`LoginId`)가 같은 코드를 쓴다.
- 노드 목록과 메일함은 한 모듈이다. 부모-자식 규칙(깊이, 이름, 메시지 방향)이 둘을 함께 보고, `done`처럼 둘을 한 트랜잭션에서 바꿔야 하기 때문이다.
- DB 변경(새 테이블, 열, 자료 옮기기)은 파일 하나로 더한다: `src/db/changes/<UTC yyyymmdd-hhmm>-<이름>.sql`. 문서와 커밋은 변경을 이 파일 이름으로 가리킨다. 자세한 규칙은 [저장](저장.md) 「DB 변경」에 있다.

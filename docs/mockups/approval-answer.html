승인 요청을 알림에서 바로 답하기

사람 지시: 「승인 요청도 알림에서 바로 처리할 수 있게 못하나」 「승인해야할 내용 보여주고 버튼 옵션 선택할 수 있게」. 점선이 바뀌는 곳이다. 그림의 승인 창 글은 실제 화면에서 옮겼다(Claude Code 2.1.309, Codex 0.159.2, Cursor는 저장소 시험 화면).

지금 승인 창 줄

  • Q14워커 배포 · 승인 요청
    Claude needs your permission to use Bash
  • 무엇을 승인하는지(명령) 보이지 않는다. 답하려면 그 노드 터미널로 가야 한다.

  • Q15워커 검사 · 승인 요청Codex
    Would you like to run the following command? Reason: 현재 환경은 읽기 전용입니다. 파일을 만들도록 허용하시겠습니까? $ touch zz_file

    터미널의 승인 창이 바뀌었습니다. 보내지 않았습니다. 터미널에서 확인하세요.

  • Q16워커 화면 · 승인 요청Cursor
    $ mkdir zz_dir in . Run this command? Not in allowlist: mkdir
  • 알약 한 줄에 무엇을 승인하는지 보인다(Q14: 「Bash git push origin main」).
  • 목록 줄에 터미널 승인 창의 본문(도구, 명령, 이유)을 터미널 글자로 그대로 보인다.
  • 승인 창의 선택지를 그 순서와 원래 글 그대로 버튼으로 보인다. 키 칸(1, y, tab)은 터미널에서 누르는 키다. 터미널의 기본 선택(첫 줄)을 주황 테두리로 보인다.
  • 버튼을 누르면 데몬이 그 노드 터미널에 그 키를 보낸다. 승인 창이 닫히고 에이전트가 다시 일하면 줄이 사라진다.
  • 보내기 전에 데몬이 터미널 화면을 다시 읽는다. 승인 창이 없거나 글·선택지가 바뀌었으면 보내지 않고 빨간 글로 알린다(Q15). 다른 창에 키가 들어가지 않는다.
  • [터미널에서 답하기]는 그대로 둔다. 명령을 고쳐 답하거나(Claude 「Tab to amend」) 글을 써서 답할 때 쓴다.
  • 화면에서 본문·선택지를 읽지 못한 승인 대기는 지금처럼 한 줄 글과 [터미널에서 답하기]만 보인다.

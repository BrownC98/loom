# 레이어

기능 역할로 나눈다. 의존은 위에서 아래로만 둔다. 기능 모듈끼리는 서로 부르지 않는다.

상호작용 레이어에는 아래 Rust 모듈 말고 화면(`web/`), 데스크톱 앱 창(`app/`), 폰 앱(`android/`)도 있다. `tests/layers`가 `cargo test`(Linux)에서 아래 세 표를 읽고 `src/`의 `crate::` 경로와 `use`를 검사한다(`#[cfg(test)]` 코드는 뺀다). 표에 없는 모듈, 위로 가는 의존, 기능 모듈끼리의 호출(값 타입 표의 타입만 된다), 모듈 순환이 있으면 실패한다. 예외 표에 있는 의존만 통과한다.

| 모듈 | 레이어 | 맡는 일 |
|---|---|---|
| `main` | 상호작용 | 진입점과 CLI 인자 정의(`src/main.rs`) |
| `cli` | 상호작용 | CLI 명령(`src/cli.rs`) |
| `daemon` | 조합 | 데몬 라우트. `src/daemon.rs`는 공유 상태(`App`, `Problem`)와 라우터 조립이다. 묶음별 파일은 `src/daemon/`의 `nodes.rs`·`repos.rs`·`waits.rs`(대기·문서)·`commands.rs`(에이전트 명령)·`system.rs`(파일·갱신·이벤트·화면 파일)이고, 설정·계정·사용량은 `settings.rs`, 노드 실행·재개는 `runtime.rs`다. 아래 모듈을 부르고 결과를 엮기만 한다. 예: 워크트리 닫기는 그래프의 `running` 수, `worktree::close`, 노드 지우기를 차례로 부른다 |
| `graph` | 기능 | 그래프(`src/graph/`: 노드 목록, 메일함, 이벤트 기록, 사람 응답 대기(`waits.rs`)) |
| `node_host` | 기능 | 노드 호스트(`src/node_host/`: PTY 호스트에 붙어 출력 나누기, 중단할 셸(`mod.rs`), PTY 호스트 프로세스(`host.rs`), 프레임(`wire.rs`)) |
| `worktree` | 기능 | 저장소와 워크트리(`src/worktree.rs`: 저장소 목록, `git worktree` 읽기·만들기·닫기) |
| `commit_graph` | 기능 | 커밋 그래프(`src/commit_graph.rs`: `git log` 읽기) |
| `profile` | 기능 | 프로필(`src/profile.rs`: 에이전트 카탈로그와 시작 명령, `src/profile/claude.rs`: Claude 시작 인자와 훅 입출력, `src/profile/codex.rs`: Codex 시작 인자와 메일함→`turn/*` 규칙, `src/profile/codex/server.rs`: app-server 프로세스와 JSON-RPC 연결, `src/profile/opencode2/`: OpenCode 2 규칙과 전달 작업(`mod.rs`), 서버 프로세스와 HTTP 연결(`server.rs`)) |
| `screen` | 기능 | 화면 확인 창 찾기(`src/screen.rs`) |
| `accounts` | 기능 | 계정(`src/accounts.rs`) |
| `usage` | 기능 | 사용량(`src/usage.rs`) |
| `settings` | 기능 | 설정(`src/settings.rs`) |
| `roles` | 기능 | o-mode 역할 표(`src/roles.rs`: 역할마다 에이전트·모델·강도와 책임) |
| `devices` | 기능 | 짝지은 폰 기기와 초대(`src/devices.rs`) |
| `spots` | 기능 | 화면 그래프의 노드·저장소 자리(`src/spots.rs`) |
| `tailscale` | 기능 | Tailscale로 데몬 열기(`src/tailscale.rs`: `tailscale serve` 상태 읽기·바꾸기) |
| `update` | 기능 | loom 새 판 받기와 바꾸기(`src/update.rs`) |
| `user_doc` | 기능 | user-doc 문서 확인·기록·붙이기(`src/user_doc.rs`) |
| `paste` | 기능 | 붙여 넣은 파일 저장(`src/paste.rs`) |
| `protocol` | 기반 | 데몬·CLI·화면이 함께 쓰는 API 타입과 loom 판(`src/protocol.rs`: 메시지 종류와 전달(`Kind`, `Delivery`), `VERSION`) |
| `launch` | 기반 | 데몬 켜기·끄기(`src/launch.rs`: `loom open`·`loom stop`, 데몬 잠금과 `daemon.json`, 떼어 띄우기). 데몬과 갱신도 잠금과 떼어 띄우기를 쓴다 |
| `db` | 기반 | DB(`src/db.rs`: 파일 열기와 스키마 변경 목록) |
| `git` | 기반 | git(`src/git.rs`: `git` CLI 부르기, Windows에서 WSL 저장소는 그 배포판의 git) |
| `wsl` | 기반 | WSL(`src/wsl.rs`: `\\wsl.localhost\…` UNC와 Linux 경로 바꾸기, 배포판 값 읽기, 노드를 배포판에서 띄우는 `wsl.exe` 명령) |
| `process_tree` | 기반 | 프로세스 나무(`src/process_tree.rs`: 자손 찾기와 끝내기, OS마다 다른 프로세스 코드) |
| `search_path` | 기반 | 찾기 `PATH`(`src/search_path.rs`: 실행 파일을 찾을 `PATH`, Windows에서 레지스트리 `Path` 새로 읽기) |
| `timed` | 기반 | 시간 제한 있는 명령 실행(`src/timed.rs`) |
| `open` | 기반 | 파일·주소를 OS 기본 프로그램으로 열기(`src/open.rs`) |
| `task` | 기반 | 노드 작업 폴더의 이름과 파일(`src/task.rs`: `LOOM_TASK_DIR`, `brief.md`, `result.md`) |
| `link_text` | 기반 | 글에서 경로·주소 링크 찾기(`src/link_text.rs`) |
| `choices` | 기반 | 질문 끝의 선택지 읽기(`src/choices.rs`) |
| `skills` | 기반 | 내장 스킬 파일과 플러그인 경로(`src/skills.rs`) |
| `pake` | 기반 | 기기 짝짓기 암호 교환(`src/pake.rs`) |
| `fake_exe` | 기반 | 테스트용 가짜 실행 파일(`src/fake_exe.rs`, 테스트에서만 빌드한다) |

예외 표는 아직 고치지 않은 위반이다. 검사는 표의 항목을 통과시키고 순환 검사에서도 뺀다. 고친 항목이 표에 남으면 실패하므로 표는 줄기만 한다.

| 의존 | 항목 | 고칠 방법 |
|---|---|---|
| `profile` → `screen` | `Answer`, `Dialog`, `Grammar`, `LinePrompt`, `Options`, `Place`, `Reply`, `Session`, `Top`, `find`, `line`, `prompt` | `screen`을 `src/profile/`로 옮기거나 기반에 둔다 |
| `profile` → `node_host` | `Screen` | 화면 내용 타입을 기반으로 옮긴다 |
| `graph` → `profile` | `profile_of` | 데몬이 프로필을 구해 그래프에 넘긴다 |
| `roles` → `profile` | `check_choice`, `check_known_choice` | 데몬이 모델 확인 결과를 넘긴다 |
| `settings` → `roles` | `RoleProblem`, `Roles`, `SetRole` | `roles`를 `settings`에 합치거나 데몬이 엮는다 |
| `accounts` → `profile` | `color_terminal` | 기반 모듈로 옮긴다 |
| `usage` → `accounts` | `Site` | 데몬이 값을 넘기거나 `Site`를 기반으로 옮긴다 |
| `user_doc` → `devices` | `random_token` | 기반 모듈로 옮긴다 |

- `Profile`은 메시지 연동이고 `Provider`는 계정이다. OpenCode 2와 Cursor는 프로필은 있고 공급자는 없다. Cursor 노드는 Cursor CLI의 로그인을 쓴다.
- 프로필의 전달 작업은 그래프를 모른다. 데몬이 노드 메일함을 `profile::Mailbox`(꺼내기와 변화 알림)로 넘긴다.
- 노드 호스트는 키에 대해 제네릭이다. 노드 PTY(`NodeId`)와 로그인 창 PTY(`LoginId`)가 같은 코드를 쓴다.
- 노드 목록과 메일함은 한 모듈이다. 부모-자식 규칙(깊이, 이름, 메시지 방향)이 둘을 함께 보고, `done`처럼 둘을 한 트랜잭션에서 바꿔야 하기 때문이다.
- 새 테이블은 `src/db.rs`의 `STEPS` 끝에 항목 하나로 더한다. 마이그레이션은 `rusqlite_migration`(`PRAGMA user_version`)이 한다.
